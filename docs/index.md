# LiveKit Provider

An unofficial, community-maintained provider for [LiveKit Cloud](https://livekit.io/cloud), built on the
[LiveKit Cloud API](https://beta-api.livekit.cloud/v0/openapi). It manages the configuration of LiveKit
Cloud projects: their settings, webhooks, API keys, members, SIP trunks and dispatch rules, and phone
numbers. It supports both OpenTofu and Terraform.

Use the full `registry.opentofu.org/solcreek/livekit` source address with either CLI.

~> The LiveKit Cloud API is LiveKit's pre-GA `v0` API: its endpoints and fields can change without notice.

## Example Usage

```terraform
terraform {
  required_providers {
    livekit = {
      source = "registry.opentofu.org/solcreek/livekit"
    }
  }
}

# The session comes from LIVEKIT_SESSION_TOKEN, or else from the LiveKit CLI
# after `lk cloud auth`. A session reaches every project its user belongs to,
# so name the project to manage.
provider "livekit" {
  project_id = "p_abc123"
}

# To manage several projects, such as production and staging, give each a
# provider alias.
provider "livekit" {
  alias      = "staging"
  project_id = "p_def456"
}

# Guard against applying a configuration to the wrong project.
data "livekit_project" "this" {}

check "project" {
  assert {
    condition     = data.livekit_project.this.name == "Acme"
    error_message = "The default provider must point at the Acme project."
  }
}
```

## Authentication

The LiveKit Cloud API accepts only a **user session**: there are no service accounts or long-lived
tokens for it yet. The provider takes the session from, in order:

1. the `session_token` argument;
2. the `LIVEKIT_SESSION_TOKEN` environment variable;
3. the LiveKit CLI configuration (`~/.livekit/cli-config.yaml`, or `cli_config_path`), where
   `lk cloud auth` saves a session for its default user (or `cli_user`).

A session lasts about 30 days and cannot be refreshed. The provider refuses an expired session from the
CLI configuration and warns a week before it expires. In CI, store a session token as a secret and
replace it before it expires.

A session reaches every project its user is a member of, with the user's role in each: `1` (read) for
data sources, `2` (write) for webhooks, and `3` (admin) for project settings and API keys. Name the
project with the provider's `project_id` (or `LIVEKIT_PROJECT_ID`), or per resource, and use a provider
alias per project. A project the user cannot see answers `404`, like one that does not exist.

The provider does not use a project's API key and secret, which only reach the LiveKit server API.

## Lifecycle behavior

- `livekit_project_settings` manages only the settings that the configuration sets; destroying it
  leaves the project as it is. The API cannot clear `enabled_codecs` or `pii_redaction_categories`, so
  those need at least one element.
- `livekit_api_key` defaults to `deletion_protection = true`: a deleted key cannot be restored, and
  every server and webhook that uses it stops working. Keys have no update, so a changed
  `description` or `service_account` replaces the key, which the protection refuses. Apply `false`
  before destroying or replacing one.
- Existing objects are adopted with `terraform import`, never by matching a name or a URL. The API does
  not return the secret of an existing key, so it stays empty after an import.
- A webhook keeps the ID of its signing key after that key is deleted, and its deliveries then cannot
  be verified. Point the webhook at another key before deleting the one it uses.
- SIP trunks and dispatch rules change in place. The API replaces them whole, so the provider reads each
  one, overwrites the fields it manages and sends the rest back unchanged. SIP passwords are write-only:
  the API answers `********`, so only a removed password is detected.
- Phone numbers must be in E.164 format; the API silently adds a missing `+`.
- `livekit_project_member` manages members of private projects only, never adopts an existing member,
  never removes the user Terraform runs as, and never removes a member who owns API keys.
- **Creating a `livekit_phone_number` buys the number**, which costs money; destroying it releases it
  for good. It defaults to `deletion_protection = true`.
- Secrets (`livekit_api_key.secret`, SIP `auth_password`, dispatch rule `pin`) are marked sensitive but
  are stored in the state, like every attribute. Protect the state accordingly.

## Schema

### Optional

- `api_url` (String) LiveKit Cloud API base URL. Defaults to `https://beta-api.livekit.cloud`. Falls back to `LIVEKIT_API_URL`, the variable the LiveKit CLI reads too.
- `cli_config_path` (String) LiveKit CLI configuration to read the session from when no token is set. Defaults to `~/.livekit/cli-config.yaml`. Falls back to `LIVEKIT_CLI_CONFIG`.
- `cli_user` (String) ID or email of the signed-in user in the LiveKit CLI configuration whose session to use. Defaults to the CLI's default user.
- `project_id` (String) Default project (`p_...`) for resources and data sources that do not set their own `project_id`. Falls back to `LIVEKIT_PROJECT_ID`.
- `session_token` (String, Sensitive) A LiveKit Cloud user session token. Falls back to the `LIVEKIT_SESSION_TOKEN` environment variable, and then to the session that `lk cloud auth` saved in the LiveKit CLI configuration. A session lasts about 30 days.
- `timeout_seconds` (Number) Per-request HTTP timeout in seconds. Defaults to 60.
